# Output Contract

## Required Shape

UI Surface, Source Mapping, State/API Flow, Design-System Pattern, Edge States, Accessibility/Responsive Notes, Tests, Verification.

## Always Include

- Summary
- Evidence Reviewed
- Risk Level
- Confidence
- Recommendation or Change
- Verification
- Open Questions or Blockers

## Quality Bar

- Specific file paths or runtime signals beat generic advice.
- Explain why a risk matters, not just that it exists.
- Make the next step executable.
